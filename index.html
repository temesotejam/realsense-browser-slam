T265-cumulative STATIC + RGB-D persistent-map localization

Build 25 uses T265 relative orientation as the primary short-term rotation source and also uses T265 relative translation as a sanity guard for D435 Depth ICP. T265 absolute world coordinates are still not used as the map coordinate system. If ICP translation agrees with T265 within a lever-arm allowance, Depth ICP translation is retained and T265 rotation is applied. If ICP translation becomes implausible during a large turn, the system temporarily enters T265_BRIDGE and advances with the T265 relative rigid motion until Depth tracking becomes usable again. New keyframes are not created while bridged. Each keyframe stores the T265 pose snapshot from that instant. Build 24 uses that not only as an ICP initial guess, but also to rank physically nearby keyframes before visual/depth verification. The original trusted keyframe is explicitly kept in the candidate set when T265 says the camera is near it. STATIC exit now uses cumulative T265 motion measured from the instant STATIC latched. RGB translation/rotation/scale count as one RGB sensor vote instead of three independent votes, and RGB/ICP jitter cannot release STATIC while cumulative T265 still says the camera is stationary unless Depth geometry also corroborates motion. T265 pose is converted from its X-right/Y-up/Z-back basis into the D435 optical X-right/Y-down/Z-forward basis before fusion. Map locks and relocalization remain the authority for long-term absolute coordinates. T265/Depth agreement can verify large map corrections only when T265 also says the selected keyframe is physically nearby. Large T265-assisted corrections require three consecutive confirmations, and RGB identity evidence is still required. A new keyframe is also suppressed when T265 says an existing keyframe is within 6 cm and 4°. Normal odometry still includes an adaptive zero-motion gate. Fresh RGB samples are numbered so repeated descriptors cannot add votes. When RGB geometry and ICP indicate no motion, the D435 block-Depth noise floor is learned online and the Depth threshold adapts to that sensor/scene. Four consecutive fresh RGB confirmations freeze pose as STATIC. Once latched, map anchoring and odometry integration cannot move the pose; only confirmed real motion releases the latch. During motion, T265 relative pose initializes frame-to-frame ICP; if that solve is weak, a T265-pose retry is attempted. Translation disagreement is checked against a lever-arm-aware gate. Large-turn ICP translation failures are bridged by T265 rather than immediately entering LOST. The first map keyframe is now created immediately at session start and marked trusted, so the original static location becomes the map origin before motion begins. If the trusted keyframe is still geometrically reachable, it is preferred so drifted provisional keyframes cannot become the only reference. This local keyframe ICP limits short-term drift while preserving the global relocalization layer. Each map keyframe stores metric Depth plus RGB corner features and 128-bit local descriptors. Revisits are ranked by RGB appearance, checked for 2D geometric consistency, then verified by forward + reverse 3D Depth ICP. Large pose corrections require strong RGB geometry plus low Depth error. Recovery and medium/large loop closures must match the same keyframe twice before the pose is moved. Once tracking is LOST, odometry alone is not allowed to resume: a verified map match is required. When relocalization succeeds in BUILD mode, only the untrusted segment created since the last accepted map anchor is rigidly repaired back into the matched map frame. Earlier trusted keyframes are left untouched. If RGB is active, recovery never falls back to Depth-only because of a temporarily weak RGB frame. A verified revisit anchors the current 6DoF pose back to the stored map coordinates. Save Map preserves both Depth and RGB features.
